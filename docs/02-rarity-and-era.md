# 02. レア度計算と時代補正

## 2.1 基本レア度の確率分布

仕様書の分布（★1〜10）:

| ★ | 確率 | 累積 |
|---|------|------|
| 1 | 40%   | 40%    |
| 2 | 25%   | 65%    |
| 3 | 15%   | 80%    |
| 4 | 10%   | 90%    |
| 5 | 6%    | 96%    |
| 6 | 2%    | 98%    |
| 7 | 1%    | 99%    |
| 8 | 0.4%  | 99.4%  |
| 9 | 0.1%  | 99.5%  |
| 10| 0.01% | 99.51% |

> ✅ **確定（Q2解決済み）: 余り 0.49% は ★1 に加算。**
> 合計99.51%で0.49%不足する分は、最も自然で優しい挙動として **★1へ寄せる（案A）**。
> 実装上は「どのしきい値にも当たらなければ★1を返す」だけで成立し、★1の実効確率は 40.49% になる。

### 実装（整数しきい値＋確定・案A）

判定は **f64 を経由せず整数比較**で行う（離散決定の言語間byte一致のため。[08] 8.4）。

```
# RARITY_CUM は仕様の出典（確率）。実判定はその整数版を使う。
RARITY_CUM        = [0.40, 0.65, 0.80, 0.90, 0.96, 0.98, 0.99, 0.994, 0.995, 0.9951]
RARITY_CUTOFFS_U32 = floor(RARITY_CUM[i] * 2^32)   # TS/Rust 同一のハードコード定数
  = [1717986918, 2791728742, 3435973836, 3865470566, 4123168604,
     4209067950, 4252017623, 4269197492, 4273492459, 4273921956]

baseRarity(seed):
  x = u32be(substream(seed, "rarity")[0:4])   # 0..2^32-1（先頭4byte, big-endian）
  for i in 0..9:
    if x < RARITY_CUTOFFS_U32[i]: return i + 1
  return 1                                     # 案A(確定): 余り→★1 (実効★1=40.49%)
```

- `u32be`/`substream` は [01] 1.3 の定義。**float を一切使わない**ので、Swift/Kotlin移植でも
  バケット境界が飛ばない（[01] 1.3 NOTE / [08] 8.4 で確定した方針）。
- しきい値は**式から都度計算せず、上記の十進リテラルを TS/Rust に直書き**（丸め差の持ち込み防止）。
- 連続値（色違い・保存状態）は従来どおり f64（[04] / [08] 8.4）。
- 分布テストは多数シードでヒストグラムが上表に収束することを確認する（参照実装 `distribution.test.ts`）。

## 2.2 QR年代 → 時代補正

QRの**生成年（現実世界）**から年代を求め、補正値を加算する。

| 年代 | 補正 |
|------|------|
| 2020年代 | +0 |
| 2010年代 | +1 |
| 2000年代 | +2 |
| 1990年代 | +3 |
| 1980年代 | +4 |
| それ以前 | +5 |

```
eraBonus(year):
  if year >= 2020: return 0
  if year >= 2010: return 1
  if year >= 2000: return 2
  if year >= 1990: return 3
  if year >= 1980: return 4
  return 5
```

### 取得可否と補正の適用（確定 — Q1解決済み）

QRコード規格に生成日時フィールドは存在せず、年が取れるのは内容が日時を含む場合のみ
（vCardの`REV`、iCalの`DTSTAMP`、一部URLのタイムスタンプ等）。これを踏まえ方針を確定:

> ✅ **確定方針**
> - QRの生成日時が**取得できた場合のみ**、時代補正（+0〜+5）を適用する。
> - **取得できない場合は補正 +0** とする（大多数のQRはこちら）。
> - 遺物の**時代設定（遺物時代）は別軸の擬似年代ストリーム（ハッシュ `"era"`）で決定**し（[03] 3.3）、
>   年が取れないQRでも**時代の多様性は常に確保**される。
> - 未来の年代（2030年代〜）は範囲外として +0。不正値（極端な過去/未来）は「取得できなかった」扱い。

```
eraBonusFor(qr):
  year = extractYear(qr)            # qr/timestamp: 取れなければ null
  if year is null:        return 0  # 補正なし。遺物時代の多様性はハッシュ"era"が担保
  if year < 1900:         return 0  # 不正値は取得失敗扱い
  return eraBonus(year)             # 上表（2030年代以降は >=2020 枝で +0）
```

#### この方針が満たすもの
- **世界観**: 時代補正が効かないQRでも、遺物自体は古代〜未来まで多彩に出る（`"era"`ストリーム）。
- **技術要件**: 取得不能が大多数でも破綻せず、取れたQRには「現実の古さ」ボーナスが正しく乗る。
- **決定論**: スキャン時刻を一切使わない。同じQRは年抽出結果も補正も常に同じ。

#### 2つの「時代」の独立性（再掲・重要）
- `eraBonus`（QR年代・現実）と 遺物時代 `era`（架空・ハッシュ）は**完全に別軸**。
  年が取れてもレア度に効くだけで、遺物が古代になるとは限らない。逆も同様。

## 2.3 最終レア度と ★11〜13

```
finalRarity = clamp(baseRarity + eraBonus, 1, 13)
```

- `baseRarity` 1..10、`eraBonus` 0..5 → 素の和は 1..15。**上限★13でクランプ（確定 / Q5）**。
- ★11〜13は和が11以上のとき自然発生（仕様の例: ★9+3=★12, ★10+3=★13）。
- 和が14,15になるケース（例 ★10+5=15）は★13に丸める。★13の上振れぶんは「神話級の希少さ」として許容。

### ★11〜13 は「本物の古いQR」でのみ到達する神話級（重要な設計的含意）

`eraBonus` は **QRの生成日時が抽出できた場合にのみ** 1以上になる（[02] 2.2 / Q1）。
日時が取れないQRは `eraBonus=0` ＝ `finalRarity = baseRarity ≤ 10`。

> **つまり ★11〜★13 は、日時が抽出でき、かつ現実に古いQRからしか出ない。**
> - ★13到達例: baseRarity10 + 1990年代(+3)、baseRarity8 + 1980年以前(+5) など。
> - 日付なしの大多数のQRからは、どれだけ引いても最高★10で頭打ち。

これは世界観として強い意味を持つ: **「古代の遺物の最高傑作（神話級）は、
現実世界でも古い由緒あるQRからしか発掘されない」**。収集の最終目標として自然に機能する。

### 表示と内部の分離
- **DB選択に使うのは `baseRarity`**（[00] 0.2、[03]）。`finalRarity` は表示・図鑑の価値判定のみ。
- 図鑑では `finalRarity` を星表示。★11〜13は専用フレーム/演出を割り当てると収集動機になる。

## 2.4 保存状態への軽い相関（仕様6章の許容範囲）

「レア度が高いほど保存状態が良い確率が上がる軽い補正は許容」。
これは色違い・レイヤー側の `"preserve"` ストリームにバイアスを掛けて実装する（[04] 4.4）。
**レア度の決定自体は色と独立**（[01]）のまま、保存状態だけ弱く相関させる、という非対称設計。
