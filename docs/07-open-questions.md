## Q1 ✅【解決済み】QRから「生成日時」をどう得るか（時代補正の根幹）

**決定（2026-06-12）:**
- QRの生成日時が**取得できた場合のみ**、時代補正（+0〜+5）を適用。
- **取得できない場合は補正 +0**。
- 遺物の**時代設定は別軸の擬似年代ストリーム（ハッシュ `"era"`）で決定**し、
  年が取れないQRでも時代の多様性を確保。

→ 世界観・技術要件・決定論をすべて満たす最適解として確定。
実装は [02] 2.2（`eraBonusFor`）と [03] 3.3（遺物時代 `"era"`）に反映済み。
未確定の細部は Q5（クランプ）・Q8（範囲外/不正値）に分離。Q8は「範囲外+0・不正値は取得失敗扱い」で本決定に内包。

### `extractYear` の抽出対象／抽出禁止項目

`qr/timestamp.extractYear(qr) -> year | null` は、**内容に明示的な日時が含まれる場合のみ**年を返す。
推測・近似はしない（決定論と「現実の古さ」要件のため）。判定対象を以下に固定する。

**✅ 抽出対象（明示的な日時を持つ構造のみ）**
| 形式 | 抽出元 | 例 |
|------|--------|-----|
| vCard / MeCard | `REV:` フィールド（改訂日時） | `REV:2014-03-10T...` → 2014 |
| iCalendar (VEVENT) | `DTSTAMP:` / `DTSTART:` | `DTSTAMP:20081231T...` → 2008 |
| URL内の明示的タイムスタンプ | パス/クエリのISO日付 or UNIX時刻（10/13桁） | `?t=1577836800` → 2020 |
| 構造化テキストの ISO 8601 日付 | `YYYY-MM-DD`（前後が数値で曖昧でないもの） | `2011-05-01` → 2011 |

複数候補が取れた場合は **最も若い（新しい）年**を採用（保守的＝補正を過大にしない）。

**🚫 抽出禁止（年を推測しない＝必ず `null` → 補正+0）**
- QRそのもののスキャン時刻・端末時計（決定論違反。絶対に使わない）。
- バイナリQR、Wi-Fi設定、決済コード、プレーンURL・プレーンテキスト等、日時を持たない内容。
- 電話番号・郵便番号・連番・価格など、**日時でない数値の年への流用**（誤検出防止）。
- 相対表現（「3日前」等）や曖昧な2桁年（`05` が1905か2005か不明）。
- 範囲外（2030年代以降）・不正値（1900年以前）は取得しても `null` 扱い（Q8）。

## Q2 ✅【解決済み】基本レア度分布の合計が 99.51%（0.49%不足）

**決定（2026-06-12）: 余り0.49%は ★1 に加算（案A）。** 最も自然で優しい。
- ★1の実効確率 = 40.49%。実装は「どのしきい値にも当たらなければ★1」だけ。[02] 2.1 に反映済み。

## Q3 ✅【解決済み】容量2GB と DB規模

**決定（2026-06-12）:**
- レコード数 **5,000〜10,000**
- アングル **1枚**
- 色違い・汚れ・破損は**実行時レイヤー合成で無限化**
- 総容量 **1.2〜1.4GB**（2GB枠内）

→ ベース画像 ~43KB/枚を確保でき現実的。無限感はレイヤー/色/テキストで担保（[04] 4.6）。
[05] 5.4・[03] 3.1 に反映済み。将来のアングル追加は擬似3Dで実体を増やさず対応する余地あり。

## Q5 ✅【解決済み】補正後レア度のクランプ仕様

**決定（2026-06-12）: 最終レア度は ★13 でクランプ。** 和14,15の上振れは神話級の希少さとして許容。
- **設計的含意（重要）: ★11〜13 は `eraBonus≥1` が必要 → 日時が抽出でき現実に古いQRからのみ到達。**
  日付なしQRは最高★10で頭打ち。「本物の古いQRでのみ出る神話級」として機能（[02] 2.3）。

## Q6 ✅【解決済み】「同じQR」の正規化強度

**決定（2026-06-12）: 軽い正規化のみ（[01] 1.1）。**
- **吸収する**: URLのホスト名小文字化・末尾スラッシュ・クエリのキー順。
- **正規化しない**: パスの大文字小文字、クエリの値、フラグメント。
- **テキストQR・バイナリQR**: 生データそのまま（バイナリは無加工、テキストは末尾空白除去のみ）。

## Q7 ✅【解決済み】バージョニング時の旧遺物の見せ方

**決定（2026-06-12）:**
- バージョンアップ時、旧遺物は**完全再現しない**。
- **現行ロジックで近似再現**し、UIに **「旧バージョン生成」注記**を表示。
- **旧DB・旧テンプレートは保持しない**（容量・実装をシンプルに保つ）。

→ [06] 6.4 に反映済み。厳密な「同じQR=同じ遺物」は同一 `genVersion` 内で保証、
版跨ぎは注記で明示（「研究の進展で復元像が更新された」という世界観解釈で許容）。

## Q8 ✅【解決済み】未来年代・不正日時の扱い

**決定（2026-06-12）: 範囲外は +0、不正値は「年代取得不可」扱い。** 最も安全で決定論も壊れない。
- 2030年代以降（範囲外）: `eraBonus = +0`。
- 1900年以前など異常値: 「年代取得不可」扱い → 補正なし（[02] 2.2 `eraBonusFor` で `year<1900` 枝）。
- 取得不可でも遺物時代の多様性はハッシュ `"era"` が担保（Q1）。

## 変更可能性による分類（重要）

確定した決定を「**変えてはいけない中核仕様**」と「**バランス調整で変えてよい項目**」に分ける。
前者を破壊的に変えると `genVersion` を上げざるを得ず、既収集遺物が別物になる（[06] 6.4）。
後者は同一 `genVersion` のまま調整できる、または見た目だけの調整で決定論に影響しない。

### 🔒 変更不可の中核仕様（変えると同じQRから別遺物が出る → genVersion更新が必須）
| 該当 | 中核ルール | 根拠 |
|------|-----------|------|
| Q1 | 「日時が取れた時のみ補正・取れなければ+0」という補正の入口ルール | [02]2.2 |
| Q2 | レア度の累積しきい値と「余りは★1」 | [02]2.1 |
| Q4 | civ/era/category/baseRarity をハッシュ独立ストリームで決める方式・**タグ名** | [01]1.3 / [03]3.3 |
| Q5 | `finalRarity = clamp(baseRarity+eraBonus, 1, 13)` の式と上限13 | [02]2.3 |
| Q6 | 正規化の吸収/保持の境界（どこを正規化するか） | [01]1.1 |
| Q8 | 範囲外+0・不正値nullの判定境界（1900未満/2030以降） | [02]2.2 |
| 共通 | RNGの派生方式・バイトオーダ・合成レイヤー順序・artifactHashの導出 | [01]1.3 / [00]0.4.3 / [06]6.1 |

> これらは「同じQR＝同じ遺物」の不変条件そのもの。変更時は必ず `genVersion` をインクリメントし、
> 旧遺物は近似再現＋注記で扱う（Q7）。

### 🔧 変更可能な調整項目（バランス調整・拡充。決定論や互換に影響しない範囲）
| 該当 | 調整してよいもの | 注意 |
|------|-----------------|------|
| Q3 | レコード数（5,000〜10,000の範囲内）、画像解像度、圧縮品質、キャッシュ上限 | 体験・容量の調整のみ |
| Q4 | `*_WEIGHTS`（civ/era/category の重み配分） | 出現比率が変わる＝厳密には版差。大きく変えるなら genVersion 検討 |
| — | 名前付き色の領域定義、汚れ/破損レイヤーの**ブレンドモード以外**の見た目調整 | ラベル・素材差し替えは表示のみ |
| — | テンプレート**文面**（スロット構造・キー名は固定／[04]4.5） | 文面変更は版差になりうる→注記で吸収 |
| — | レイヤーPNG・背景アセットの素材そのもの（寸法上限は固定） | 見た目の改善 |
| — | UI・図鑑の演出（★11〜13の専用フレーム等）、フォールバックの内部最適化 | 出力遺物に影響しない |

> 「重み」「文面」は厳密には出力を変えるため、**大幅変更時は genVersion を上げる**判断を [06] 6.4 に従って行う。
> 小さなバランス調整は同一版内で許容（注記で吸収）。

## 付録A: 将来拡張の候補（未着手・設計余地のメモ）

実装フェーズでは扱わないが、設計が拡張を阻害しないことを確認するための候補。
いずれも導入時は互換性（genVersion）と容量（[05]5.4）への影響を再評価する。

| 拡張 | 概要 | 設計上の受け皿 | 主な影響 |
|------|------|---------------|---------|
| **擬似3D / 多アングル** | 法線マップ簡易ライティングで角度を出す。`images.angle` を 0 以外へ | `images[].angle`（現状0固定）、合成パイプライン | 容量は実体を増やさず対応可。決定論はアングル選択も要シード化 |
| **新写真風スタイル** | museum/dig/catalog に加え「X線写真風」「3Dスキャン風」等 | `BACKGROUND[style]`、`base.imageSet[style]` | ベース画像の枚数×スタイル数が増える＝容量増。style列挙の拡張 |
| **新汚れ/破損レイヤー** | 苔・錆・落書き・封蝋など | `DIRT_LAYERS` / `DIRT_BLEND` への追記、`"dirt"` 重み | レイヤーは共有なので容量微増。重み変更は版差に注意 |
| **新文明/時代/カテゴリ軸** | 「宇宙文明」「深海カテゴリ」等 | `civilization`/`era`/`category` テーブル＋`*_WEIGHTS` | DB再生成＋全rarityマス充足（[05]5.6）。出現比率変化＝版差 |
| **★14以上の超神話級** | クランプ上限の引き上げ、専用演出 | `finalRarity` clamp（[02]2.3, 中核仕様） | 🔒中核変更＝genVersion更新必須。慎重に |
| **イベント限定補正** | 期間限定で特定QRのレア度を底上げ | — | ⚠️ 決定論と衝突しうる。実装するなら「同じQRは同じ」を崩さない設計が前提 |
| **オンデマンド高解像DL** | 同梱はサムネ、詳細時に高解像取得 | キャッシュ層、アセット解決 | オフライン要件（[00]0.1）と要相談 |

> 付録の項目は**仕様ではなく検討メモ**。着手時は本ファイルに新しい Q として起票し、
> 上の「変更不可／変更可能」分類のどちらに触れるかを最初に判定する。
