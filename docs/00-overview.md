# 00. 全体アーキテクチャと生成フロー

## 0.1 設計原則

1. **完全決定論**: 同じQR生データ → 必ず同じ遺物。実行時に乱数源を一切使わない。
2. **オフライン完結**: 端末上でLLMを動かさない。遺物データ・画像・テンプレートは事前生成し、
   アプリ内DB（〜2GB想定）として同梱する。
3. **有限DB × 無限合成**: ベース遺物は有限（**5,000〜10,000**, 確定 / [07] Q3）。色違い・汚れ・破損・
   個体差テキストをハッシュ由来で合成し、体感無限のバリエーションを作る。
4. **再生成可能 = 保存は軽量**: 図鑑には「QR生データ（または正規化済みキー）」と
   「生成時バージョン」だけ保存すれば遺物全体を再現できる。画像実体は保存しない（[06](06-data-model.md)）。

## 0.2 生成パイプライン（仕様書フローの再構成）

仕様書の10ステップを、責務が混ざらないよう並べ替えた版です。

```
QR生データ (raw bytes)
  │
  ├─(A) 正規化              … 末尾空白・URLスキーム等を吸収し「同じQR」を安定化
  │        normalizedKey
  │
  ├─(B) ハッシュ化           … SHA-256(normalizedKey)  → 256bit シード
  │        seed
  │
  ├─(C) 乱数ストリーム分割    … タグ付き派生で独立ストリームを無限に取り出す（[01]）
  │        rng("rarity"), rng("civ"), rng("color") ...
  │
  ├─(D) 属性決定（互いに独立 / 各々が別タグのRNGストリーム → 0.4参照）
  │        ├ 基本レア度 baseRarity ∈ 1..10        （優しい分布, [02]） tag="rarity"
  │        ├ 擬似年代  artifactEra                （架空, [03]）        tag="era"
  │        ├ 文明     civilization               （[03]）              tag="civ"
  │        ├ カテゴリ  category                   （[03]）              tag="category"
  │        ├ 色違い   colorMod (HSV)              （[04]）              tag="color"
  │        ├ 汚れ     dirtLayerId                 （[04]）              tag="dirt"
  │        ├ 破損     damageLayerId               （[04]）              tag="damage"
  │        ├ 保存状態  preservationScore          （[04] / 詳細は0.4.3） tag="preserve"
  │        └ 個体差テキスト textSeed              （[04] / タグ命名規則は0.4.4） tag="text:*"
  │
  ├─(E) QR日時の抽出 → 時代補正  eraBonus ∈ 0..5   （本物の現実年代のみ, [02] / 0.4.1・0.4.5参照）
  │        日時が取れた時のみ +1..+5。取れない/範囲外/不正 → +0
  │
  ├─(F) 最終レア度  finalRarity = clamp(baseRarity + eraBonus, 1, 13)
  │        ★11..13 は eraBonus≥1（＝本物の古いQR）でのみ到達する神話級
  │
  ├─(G) ベース遺物選択
  │        candidates = DB.where(civ, artifactEra, category, baseRarity)
  │        base = candidates[ rng("pick") % len ]   （0件時は6段フォールバック → 0.4.2参照）
  │
  ├─(H) 画像合成（実行時, GPU/Canvas / レイヤー構造は 0.4.3参照）
  │        compose(baseImage → HSV → dirt → damage → preservation → background)  （[05]）
  │
  ├─(I) 個体差テキスト生成
  │        renderTemplate(textSeed, base)           （[04]）
  │
  └─→ 遺物オブジェクト Artifact （[06]）
```

### 重要な分離点
- **(D)の各属性は互いに独立**。特に「色違いはレア度と独立」という必須要件は、
  ストリームをタグで分けることで構造的に保証する（[01]）。
- **ベース遺物選択(G)で使うのは `baseRarity`（1..10）**。`finalRarity`（補正後, 最大13）ではない。
  ★11〜13の遺物は「baseRarity 8〜10 の遺物 ＋ 高い時代補正」で表現される。
  → DBに★11〜13のレコードを持つ必要はない。

## 0.3 モジュール構成（実装単位）

| モジュール | 責務 | 純粋性 |
|-----------|------|--------|
| `qr/normalize` | 生データ正規化 | 純粋 |
| `core/hash` | SHA-256・タグ付き派生RNG | 純粋 |
| `core/rarity` | 基本レア度分布・時代補正・clamp | 純粋 |
| `qr/timestamp` | QRから生成日時を抽出（複数戦略＋フォールバック） | 純粋 |
| `db/artifacts` | ベース遺物DB問い合わせ・候補選択・フォールバック | I/O |
| `gen/color` `gen/layer` `gen/text` | 色・レイヤー・テキスト決定 | 純粋 |
| `render/compose` | 画像合成（端末GPU）＋キャッシュ | I/O |
| `collection` | 図鑑の永続化・再生成 | I/O |

純粋モジュールにI/Oを混ぜないこと。**決定論のテスト**（同一入力→同一出力）が純粋部分だけで完結する。

## 0.4 確定仕様の明確化（最終）

以下6点は本アプリの中核仕様。各詳細は参照先にあるが、混同・実装ブレを防ぐため本概要に明記する。

### 0.4.1 【二つの「年代」を完全分離】artifactEra と eraBonus

本アプリには性質の異なる2つの「年代」概念があり、**互いに完全独立・役割が別**。混同は厳禁。

| 概念 | 名称 | 由来 | 値域 | 役割 | 決まり方 |
|------|------|------|------|------|---------|
| 擬似年代 | **`artifactEra`** | ハッシュ（架空） | 古代/中世/近世/近代/未来 | **遺物の見た目・分類**。DB選択キーの1つ | RNG `tag="era"` |
| 本物の年代補正 | **`eraBonus`** | QRの生成日時（現実） | +0〜+5 | **レア度補正のみ** | QR日時 → 年代 → 補正表 |

- **`artifactEra`** は遺物が「いつの時代の文明のものか」という**架空属性**。常にハッシュから決まるので、
  どんなQRでも古代〜未来まで多様に出る。レア度には一切影響しない。
- **`eraBonus`** は「そのQRが現実世界でどれだけ古いか」へのボーナス。**取れた時だけ**加算（0.4.5）。
  遺物の見た目・時代分類には一切影響しない。
- 直交性: 「QRが古い(eraBonus大)」と「遺物が古代(artifactEra=古代)」は無関係に起こる。
  → 2020年代のQRから古代の遺物（補正+0）も、1985年のQRから未来の遺物（補正+4）も自然に出る。
- 実装上の別名厳守: コード/DB/ログで `artifactEra`（または `era_id`）と `eraBonus` を**別名**で扱う。
  詳細: [02] 2.2 / 2.3、[03] 3.3、README「用語の注意」。

### 0.4.2 【ベース遺物選択フォールバック：6段階】

`(civ, artifactEra, category, baseRarity)` の4キー完全一致で候補を引く。0件のマスは必ず存在するため、
**以下の6段を上から順に試し、最初に非空となった集合を採用**する。各段内の最終選択は `rng("pick") % len`
で決定論。詳細・最近傍 rarity の扱いは [03] 3.5。

```
段1: (civ, artifactEra, category, baseRarity)   ← 完全一致（本命）
段2: (civ, artifactEra, category, *        )   ← baseRarity を緩和（最近傍rarity優先）
段3: (civ, artifactEra, *,        baseRarity)   ← category を緩和
段4: (civ, *,           category, baseRarity)   ← artifactEra を緩和
段5: (civ, *,           *,        *        )   ← 文明のみ維持
段6: (*,   *,           *,        baseRarity)   ← 文明・時代・カテゴリを完全に無視し、
                                                  baseRarity のみ一致する全レコードから選ぶ
────────────────────────────────────────────────────────────────────
終端: GLOBAL_FALLBACK_ID                         ← 6段すべて空のときのみ。文明・時代・カテゴリの
                                                  いずれにも属さないダミー遺物（DB全体で1件のみ）
```

- どの段で当たっても、その集合は `ORDER BY id` で安定化してから `rng("pick")` で選ぶ（決定論維持）。
- DB事前生成時に「各 (civ, artifactEra, category) で全 baseRarity 1..10 を最低1件埋める」制約を満たせば、
  実運用上のフォールバックは段2止まりに抑えられる（[03] 3.5 / [05] 5.6）。

### 0.4.3 【画像合成レイヤー構造：6層・順序固定】

実行時合成は**必ず以下の順序**で行う（順序固定＝同属性なら必ず同じ絵＝決定論を画像まで貫徹）。
詳細・ブレンドモードは [05] 5.2。

```
1. baseImage      … ベース画像（artifactEra/civ/category/baseRarity で確定したレコードの絵）
2. HSV            … colorMod (hShift, sMul, vMul) を1パス適用（色違い / tag="color"）
3. dirt           … 汚れレイヤー（泥/砂/煤/海塩/火山灰…）を合成（tag="dirt"）
4. damage         … 破損レイヤー（摩耗→ひび→欠けの順, tag="damage"）
5. preservation   … 保存状態の最終調整（退色/くすみ/艶。preservationScore で強度, tag="preserve"）
6. background     … 写真風背景の合成（被写体の最背面に置く。スタイル名は museum/dig/catalog の3種に固定）
```

- 1〜5は被写体に対する処理、6は背景。被写体は全スタイルで同一座標・同一スケール（レイヤー共有のため）。
- `preservation`(5) は dirt/damage の強度とも連動するが、レイヤー適用としては破損の後・背景の前に置く。
- 合成結果は端末ローカルに LRU キャッシュ（[05] 5.5）。※ 設計目標。現行実装にLRUキャッシュは未実装（docs/08 §8.6）。

### 0.4.4 【RNGストリームのタグ分離（独立性の保証）】

全属性は**単一シード**から派生するが、**タグで分離した独立ストリーム**を使うため互いに無相関。
これが「色違いはレア度と独立」等の必須要件を**構造的に**保証する。詳細・棄却法は [01] 1.3。

```
seed = SHA-256(normalizedKey)

# 各決定は別タグ → 暗号学的に無相関
baseRarity   = rarityFrom( uniform(seed, "rarity")   )
artifactEra  = pickWeighted(seed, "era")
civ          = pickWeighted(seed, "civ")
category     = pickWeighted(seed, "category")
colorMod     = { h: uniform(seed,"color"), s: uniform(seed,"color.s"), v: uniform(seed,"color.v") }
dirtLayerId  = pickWeighted(seed, "dirt")
damage       = { chip: uniform(seed,"damage.chip"), crack: ..., wear: ... }
preserve     = uniform(seed, "preserve")
pickIdx      = uintBelow(seed, "pick", len)
placeName    = ... uintBelow(seed, "text:place.0"), uintBelow(seed, "text:place.1") ...
```

- 独立性の根拠: `substream(seed,tag,c) = SHA-256(seed || 0x00 || tag || u32be(c))`。
  タグが違えば出力は無相関、counter `c` で同一タグから無限ビット取得可（[01] 1.3）。
- **タグ文字列は一度決めたら変更不可**（変えると全遺物が変わる）。変更時は `genVersion` を上げる（0.4.6）。
- 唯一の意図的相関: 保存状態だけ finalRarity で**弱く**バイアス（「高レアほど保存良好」, [04] 4.4）。
  これは `preserve` ストリーム自体は独立のまま、出力に加算ゲタを乗せる非対称設計。レア度決定には逆流しない。

### 0.4.5 【QR正規化の仕様】

「同じQR＝同じシード」を安定させるため、ハッシュ前に**軽い正規化のみ**行う。詳細: [01] 1.1。

| 対象 | 処理 | 備考 |
|------|------|------|
| バイナリQR | **一切加工しない**（生バイトをそのままハッシュ） | 解釈の余地がなく無加工が最も安全 |
| テキストQR（一般） | 末尾の空白・改行・NUL を除去するのみ | 内容は変えない |
| URL: スキーム | 小文字化 | `HTTP://` → `http://` |
| URL: ホスト名 | 小文字化＋既定ポート(:80/:443)除去 | `Example.com:443` → `example.com` |
| URL: 末尾スラッシュ | 正規化（統一） | `/path/` ↔ `/path` の揺れを吸収 |
| URL: クエリ | **キー順のみソート**（値は保持） | `?b=1&a=2` → `?a=2&b=1` |
| URL: パスの大文字小文字 | **保持（正規化しない）** | 別リソースの可能性 |
| URL: クエリの値 | **保持（正規化しない）** | 〃 |
| URL: フラグメント | **保持（正規化しない）** | 〃 |

設計意図: ホスト名の大小・末尾/・クエリ順は同一リソースの表記揺れなので吸収。
パス大小・クエリ値・フラグメントは情報として有意（別ページ＝別遺物であるべき）なので保持。

### 0.4.6 【バージョニング：旧遺物は近似再現＋注記】

生成ロジック・DB・テンプレート・RNGタグを変更すると、同じQRから別遺物が出うる。これは
「同じQRは必ず同じ遺物」要件に対し、**保証範囲を同一 `genVersion` 内に限定**することで扱う。

- 破壊的変更時は `genVersion` をインクリメント。
- **旧遺物は完全再現しない。旧DB・旧テンプレートは保持しない**（容量・実装をシンプルに保つ）。
- 既収集遺物は**現行ロジックで近似再現**し、UIに **「旧バージョン生成」注記**を表示する。
- 収集時に意味のある値（`final_rarity` 等）は `collected` テーブルに保存済みなので、それは保持・表示する。
- 世界観的解釈: 「研究の進展で復元像が更新された」として版跨ぎの差異を許容。
- 詳細: [06] 6.3 / 6.4。
